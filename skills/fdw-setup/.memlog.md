- (decision) Brownfield support added. Setup asks project_stage (greenfield default, so the existing flow is untouched); brownfield additionally asks the real starting phase, accepting fractional labels like 2.1, and offers to seed the as-built baseline from a prior PRD, a handover note or dictation.
- (decision) Earlier phases are NOT synthesized. Recording phases 1 and 2 as closed with no features, no dates and no blocker counts would fabricate history, which is the one thing every skill in this module refuses to do — and it would corrupt the blocker-count trend across phases, the number the whole method is judged on. Prior work goes to as-built.md instead, stamped as recorded-at-setup and explicitly not verified by this module.
- (event) Found a latent bug while implementing: 'init --phase phase-3' already existed but produced an incoherent store — current_phase stayed phase-1, the phases list carried a phantom phase-1 with no phase.json, and validate immediately reported it unhealthy. init now decides the starting phase before writing the registry, so current_phase, the phases list and the folder on disk all agree.
- (decision) Phase ordering no longer depends on list position. Every earlier/later comparison now parses the numeric label, so phase-2.1 sorts between 2 and 3 and a phase backfilled after the fact still orders correctly. Without this, a brownfield store starting at phase-3 would invert dependency checks the moment anyone opened an earlier phase. The five-line helper is mirrored into fdw-consistency, fdw-handoff, fdw-phase and fdw-status rather than imported across skills.
