- (decision) Split cleanly along the determinism line. The script computes what is decidable — dependency cycles, topological order, phase-fit violations, glossary alias drift, orphan sources, question rollup — and proposes candidates for what is not: overlap pairs by term-set similarity, and cross-feature requirement pairs that share significant terms. The model judges only the semantic calls: is this really a contradiction, is this really the same feature twice.
- (decision) Candidate pairs are capped and ranked. A full-project run over N features is O(N squared) pairs, and handing the model thousands would either blow context or get skimmed. The script ranks by shared-term count and caps, then reports what it dropped — a silent truncation would read as nothing else found.
- (decision) This skill annotates and reports but never advances a status, per its brief. Overlap and dependency edges it confirms are emitted as feature-set commands rather than written directly, so the shared CLI stays the only writer of feature state. questions.md is different: the contract already declares it a derived rollup owned by this skill.
- (event) The canonical test passes. On the real store the audit reached the transcript's own conclusion — Events feedback first, then Academy against the reworked result — from recorded edges rather than from anyone remembering the call. It also caught something the transcript did not: Academy is spec-approved with ten requirements while both features it inherits from have no spec at all.
- (decision) Switched overlap scoring from Jaccard to the overlap coefficient after the canonical case scored 0.044 and fell below the floor. One feature is typically fully specced while the other is barely described, and Jaccard's union denominator buries exactly the case that matters — a new feature repeating most of an existing one. With the coefficient the same pair scores 0.417 and ranks first.
- (decision) Pairs already carrying a recorded overlap edge always surface regardless of score. A known overlap that scores low is still the model's to re-judge, and silently dropping it would make the audit weaker the more the BA had already annotated.
- (note) Requirement-pair candidates came back empty on the real store because only one of the three features has a spec. That is correct rather than a miss — there is nothing yet to compare — and the dependency-not-ready finding is what carries the signal at this stage.
- 2026-08-25 (decision) overlap_candidates and requirement_candidates now draw pairs scope x universe instead of scope x scope. Findings are still raised only about the scope; what changed is what they are compared against. This was a real hole: fdw-handoff/SKILL.md tells the BA to run --phase, which narrowed both sides, so a spec being written was never compared against shipped work. On the real epp store a --phase phase-3 scan now surfaces 11 pairs against delivered phase-2 work. New impact command reuses the same overlap coefficient (one metric, not two) and folds in signal_terms, which was computed and read by nothing.
