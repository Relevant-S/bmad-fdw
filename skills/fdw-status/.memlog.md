- (decision) Building fdw-status as skill 2 of 9. Chosen second deliberately: it consumes the state contract without writing to it, so the schema defined by fdw-intake gets exercised while it is still cheap to change, and every later skill becomes debuggable through a dashboard instead of raw JSON.
- (decision) This skill is mostly script. Counting, grouping, ageing questions, topological ordering, trend extraction and HTML rendering are all deterministic — pushing any of it into the prompt would be a determinism leak. The model's genuine contribution is the read of what the numbers mean and what to do next.
- (decision) Read-only by construction. The script has no write path into the store at all, so 'derived, never authoritative' is a property of the code rather than a rule the model is asked to respect.

Dependencies render as topological build-order layers computed by the script, which answers the question the BA actually has (what order do we build these).
