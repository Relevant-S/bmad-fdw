- (decision) Memory agent, not stateless. The plan specifies personal memory about the BA — how he likes specs written, phrasing preferences, question types he always wants asked — which travels with him between client engagements while the discovery store does not. That is the memory archetype by the type guidance.
- (decision) First Breath in CONFIGURATION style, not calibration. This is a focused domain tool, and the persona is explicitly allergic to process theatre; a getting-to-know-you ceremony would be exactly the thing the agent is supposed to spare the BA. Warm but quick.
- (decision) The eight workflows are referenced as installed skills, never re-authored as internal capabilities. Internal capabilities are reserved for the three things no skill covers: orienting on activation, recommending the next action, and quick registry edits — all tightly coupled to the persona and all reading through the shared state CLI.
- (note) The sanctum stays deliberately small because this agent's real state is not in the sanctum. The project lives in the discovery store, which every workflow reads and writes; the sanctum holds only what is true about this BA across engagements.
- (decision) Named Vadim, after the BA whose method this module encodes. One practical hazard designed around: the transcripts this module ingests carry a real Vadim Struk as a named speaker and signal.md attributes quotes by name, so the agent answers as Vadim but never authors as him — every state change and decision line is sourced to fdw-agent-ba, keeping the audit trail unambiguous. First Breath is told this explicitly.
- (decision) Four internal capability prompts, not three as originally planned: Orient, Next action, Quick edit, and Route. Routing deserved its own prompt because the intent-to-skill mapping is where most of the domain knowledge sits — including that ambiguity resolves from registry state rather than from asking, and that the design-before-spec ordering has to be explained before a workflow refuses it.
- (event) Wrote tests for the templated scripts to clear the one high lint finding, which doubled as the eval. Nine tests: the sanctum builds complete, config is baked into BOND, all four capabilities are discovered and registered, capability prompts reach the sanctum so it stands alone afterwards, First Breath stays behind in the bundle, a rerun never erases what the agent learned, and waking routes correctly with and without a sanctum.
- (note) Left the medium script findings — PEP 723 headers, argparse, JSON output on wake.py and init-sanctum.py. Those files come from the agent-builder's own templates, and rewriting them would fork this agent from the builder's conventions for no behavioural gain.
- (note) The Orient and Quick edit capability prompts anchor the state CLI at {project-root}/.claude/skills/fdw-intake/scripts/fdw_state.py rather than a skill-root-relative path, because init-sanctum copies these prompts into the sanctum and {skill-root} would not resolve from where they are actually read. That path is claude-code specific; on another IDE layout the agent would need the equivalent skills directory.
